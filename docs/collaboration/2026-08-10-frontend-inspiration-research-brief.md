# 势能引擎前端网站与动效参考调研 Brief

> 用途：直接交给前端 / 视觉成员执行参考调研。  
> 本轮只找方向和可复用交互，不要求改代码，也不要求先理解后端架构。

## 1. 这次需要你完成什么

请收集 **8–12 个高质量参考**，帮助我们回答两件事：

1. 势能引擎应该怎样建立“可信、精密、证据驱动”的第一印象；
2. 产品从提交想法到形成证据报告，哪些状态变化值得用动效讲清楚。

参考可以来自真实网站、Web App、Awwwards / SiteInspire / Godly / Mobbin / Figma Community、产品演示视频或 CodePen。优先选择能打开、能说明具体交互、前端可以拆解的案例，不要只交情绪板截图。

## 2. 先用一句话理解产品

**势能引擎不是“AI 猜爆款”，而是一台把产品想法送进多 Agent 评审、用真实证据推动状态、最后给出可追溯决策报告的产品验证仪器。**

核心承诺是“证据先于结论”。没有证据，盘面不前进；证据不足时明确显示缺口或假设，不制造爆款概率。

主要用户场景：创业者、产品负责人或创新团队拿着一个产品想法 / 现有版本，希望知道它在产品交付、用户需求、商业投资、时间地域四个维度上是否站得住，以及下一步最值得验证什么。

## 3. 当前体验主线

请围绕以下连续旅程找参考，而不是把每个页面当成互不相关的后台页面：

1. **公开首页**：看到评审转盘和“启动一次评审”；
2. **建立评审对象**：输入产品名，转盘从展示态进入工作态；
3. **补充四类资料**：产品材料、团队信息、用户与经营、时间与地域；
4. **确认产品画像**：区分用户填写、模型推断和仍然缺失的信息；
5. **Agent 评审运行**：主管 + 5 个专业 Agent 协作，状态和证据持续落库；
6. **需要用户时暂停**：明确指出缺什么、为什么影响判断、补充后如何继续；
7. **形成报告**：四维结论、矛盾、证据等级、信息缺口和 1–3 个行动；
8. **下一版本复验**：V2 沿用相同标准，展示改善、持平、退化与新风险。

## 4. 已确定的视觉与动效原则

这些是本轮找参考时的筛选条件，不是要推翻的方向：

- 视觉性格：**70% 专业精密仪器 + 30% 游戏任务反馈**；
- 当前母题：明亮桌面上的实体评审仪器，包含机身、刻度、内外环、校准与受控高光；
- 基础色：冷白 / 浅灰环境、石墨文字、金属黄铜；颜色主要承担状态语义；
- 状态色：信号红 = 需要注意或需要用户，校准绿 = 证据已校准，冷蓝 = 辅助信息；
- 动效必须解释真实状态：证据新增、阶段推进、Agent 交接、暂停补问、报告封存；
- 没有事件时盘面保持稳定，不能用持续热闹掩盖“没有进展”；
- 优先使用 transform / opacity，并提供 `prefers-reduced-motion` 降级；
- 桌面端和移动端都要成立，重要信息不能依赖 hover 才可见。

明确避开：

- 赌场、老虎机、抽奖转盘、夸张“中奖”反馈；
- 满屏霓虹、无含义粒子、持续眩光、过多 3D 导致信息不可读；
- 把产品做成普通聊天机器人首页；
- 假装展示 Agent 私密思维过程、虚假实时进度或虚构成功；
- 只有营销冲击力、但无法迁移到真实工作台和报告页的案例；
- 直接照搬他人的品牌资产、插画、源码或完整页面。

## 5. 重点找哪些参考

### A. 品牌首页与核心装置（优先级 P0）

找 3–4 个案例，关注：

- 单一核心装置如何在首屏承担品牌识别和主 CTA；
- 大量留白下，精密感如何成立而不显得空；
- 用户第一次点击后，核心装置如何自然让位给任务输入；
- 产品价值如何在 5 秒内被理解，而不是只留下“做得很炫”。

搜索词可从这些组合开始：

- `precision instrument web design interactive landing`
- `data instrument interface motion design`
- `editorial minimal product landing interactive object`
- `scientific dashboard visual identity`
- `精密仪器 网页 交互动效`、`数据仪表盘 状态动效`

### B. 状态驱动的产品动效（优先级 P0）

找 4–6 个案例，优先覆盖以下时刻：

| 时刻 | 希望动效解释什么 | 不希望出现什么 |
| --- | --- | --- |
| 首页待机 | 装置可被启动，但当前没有任务 | 高频旋转、抢注意力的粒子 |
| 点击中心 CTA | 从“看产品”过渡到“开始任务” | 整页硬切、突然弹出普通表单 |
| 四类资料补齐 | 哪个扇区被补全、整体还缺什么 | 与真实字段无关的假进度 |
| 新证据落库 | 盘面咬合前进一步，进展可感知 | 连续转圈冒充处理完成 |
| Agent 接棒 | 谁在做什么、任务交给了谁 | 展示私密思维链或聊天噪声 |
| NEEDS_INPUT | 系统已暂停，等待哪一项输入 | 自动重试、假装仍在运行 |
| 报告完成 | 一次评审被封存、可打开查看 | 烟花式庆祝遮挡结果 |
| V2 复验 | 新旧版本沿同一标准形成变化 | 只用颜色表达好坏 |

重点观察 easing、时长、空间方向、进入 / 退出关系、loading 和完成态的区别，以及 reduced-motion 怎么处理。

### C. 证据、报告与版本对比（优先级 P1）

找 2–3 个案例，关注：

- 关键结论如何逐层展开到来源、时间、可信度和证据；
- “证据不足 / 被降级 / 被驳回”怎样表达得严肃但不吓人；
- 四维结论怎样避免沦为普通 KPI 卡片墙；
- V1 / V2 的改善、持平、退化、新风险怎样被一眼比较；
- 长报告怎样兼顾摘要、渐进披露和可审计细节。

搜索词：

- `evidence provenance interface`
- `decision intelligence dashboard UX`
- `audit trail visualization product`
- `version comparison report UI`
- `research synthesis evidence cards`

### D. 移动端转译（优先级 P1）

至少找 1–2 个案例，关注复杂桌面仪表 / 多 Agent 侧栏如何转为移动端底部 dock、bottom sheet 或分阶段阅读。不要只找缩小版桌面页面。

## 6. 每个参考怎样回传

请使用下面的表格；每个链接只需写清一个最值得借鉴的点。

| 字段 | 填写要求 |
| --- | --- |
| 名称 + URL | 直接链接到具体页面或视频时间点，不要只给网站首页 |
| 对应环节 | 首页 / 资料输入 / Agent 运行 / 补问 / 报告 / 版本对比 / 移动端 |
| 值得借鉴 | 具体到一个布局、转场、反馈或信息层级 |
| 为什么适合势能引擎 | 对应“精密仪器、证据驱动、真实状态”中的哪一点 |
| 不应照搬 | 写清视觉、性能、可访问性或产品语义风险 |
| 落地难度 | S / M / L，并简述依赖 SVG、CSS、Motion、Canvas、WebGL 还是视频 |
| 证据 | 1 张截图，动效再附 5–15 秒录屏或时间戳 |

最后请再给出：

1. 你最推荐的 **3 个方向**，按优先级排序；
2. 每个方向能组合哪些参考、舍弃哪些元素；
3. 你建议先做的 **1 个低成本动效原型**，说明验证目标；
4. 仍然需要产品 / 设计确认的分歧，不要自行把分歧当成结论。

## 7. 评分标准

每个候选可以按 1–5 分快速自评：

- 产品语义匹配：是否真的帮助理解“证据推动评审”；
- 品牌辨识度：是否有机会形成势能引擎自己的记忆点；
- 信息清晰度：动效结束后，用户是否更清楚当前状态和下一步；
- 可落地性：现有 Next.js / React / SVG / CSS 能否合理实现；
- 性能与可访问性：移动端、键盘、对比度、reduced-motion 是否可接受；
- 可扩展性：是否能从首页延伸到运行页、报告页和 V2 复验，而非一次性特效。

优先保留总分高且“产品语义匹配”不低于 4 分的案例。

## 9. 建议交付方式

- 一个 Figma / FigJam 页面或一个 Markdown 文档；
- 8–12 个经过筛选的参考，不追求数量；
- 每个动效必须有录屏 / GIF / 时间戳，静态截图无法说明动效；
- 桌面与移动端分区；
- 结尾放 3 个推荐方向 + 1 个低成本原型建议；
- 文件中不要放账号、密钥、真实用户材料或内部环境地址。
