# Human Report Presentation Layer V0.2

## 目标

默认报告不是用户研究论文，而是给学生产品开发者看的“30 秒产品用户诊断”。内部分析能力完整保留，但前台必须让用户先看到结论和行动，再决定是否继续验证依据。

## 三级阅读路径

1. **3–5 秒：结论** —— 核心用户、可争取用户、暂不优先用户；为什么会用、为什么不用、最大问题。
2. **30 秒：行动** —— 当前 Top3 用户问题 + 下一版 Top3 修改 / 验证动作。
3. **需要时：依据** —— 六维用户价值画像、最多 2 条关键真实依据、最多 2 个下一步验证。

## 默认 5 个板块

1. 一眼看懂
2. 当前最关键的问题（≤3）
3. 下一版先改什么（≤3）
4. 为什么这么判断（紧凑六维画像 + 关键依据）
5. 下一步怎么验证（≤2）

Persona 详细建模、JTBD、完整场景、模拟访谈、隐藏需求、Hypothesis、完整 Validation Plan、评分计算、Evidence Card、Agent handoff 与日志仍保留在 Internal Machine Output，不默认展示。

## 目标客户命名

首屏目标客户必须优先使用：

`触发场景 + 需求强度 + 当前替代方案 + 切换条件`

例如优先写“面试临近、急需针对简历练习的人”，而不是“大四毕业生”。只有当年级、职业、地区本身会改变产品判断时，才作为二级说明。

## 双格式输出

- `structured_output.human_report`：简洁 Markdown。
- `structured_output.human_report_html`：同一 View Model 的 deterministic HTML，首屏与 Markdown 语义一致。

上层如果要求面向学生开发者的 Markdown / HTML，必须直接使用这两个字段，不得根据 Internal Machine Output 再扩写成长篇研究报告。

## 信息密度限制

- 主章节 ≤5
- 目标用户类型 ≤3
- Top 问题 ≤3
- 下一版动作 ≤3
- 验证动作 ≤2
- 关键依据 ≤2
- 同一核心观点默认只出现一次
- 目标约 600–1000 中文字；renderer 硬上限 1200 字符

## 证据边界

- 模拟 ≠ 真实用户；没有真实材料时必须标“模拟推演，仅供参考”。
- 30 天内再次使用默认写“30 天内复用”，除非源数据明确为标准 D30 cohort。
- 尚未正式开放收费时，0 付费不能自动解释为付费失败。
- 少量访谈只能支持“事件驱动 / 季节性迹象”，不能写成已证实季节性。
- 首体验 / 任务测试未执行时，不得编造浏览器、弱网、上传、麦克风等具体体验事实。

## Golden Case

OfferPilot 默认首屏必须在不查看详细研究过程的情况下回答：

- 给谁用？
- 谁可以争取？
- 谁暂不优先？
- 为什么会用？
- 为什么不用？
- 最大问题是什么？

Golden Case 同时生成 Markdown 与 HTML 示例。
